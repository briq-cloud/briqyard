# Architecture decision records

One file per decision, numbered, never rewritten: a changed decision is a new ADR that supersedes the old one. Research and measurements that drove a decision are in `../research/`, linked from the ADR.

Format: `# ADR NNNN: Title`, `Date · Status`, `## Context` (the problem, in a few lines), `## Decisions` (each one bold, then why), `## Consequences` (what it costs, what it rules out, when to reopen).

| [0022](0022-probes.md) | Probes in the daemon (startup, readiness, liveness: exec, TCP, HTTP), a `ready` that `/wait`, the ingress and the gateway follow, and a restart backoff doubling to 5 minutes |
| [0023](0023-scheduled-backups.md) | Backups on a schedule per machine (`every`, `keep`), run by the daemon's tick; every `keep`-th backup whole and whole chains pruned; delete; a destroyed machine's backups kept, listed and counted for `keep_destroyed_days` |
| [0024](0024-changes-at-next-boot.md) | A PATCH of the image, command, env, files, size, ports or restart is kept as `pending` and applied at the next start: a new image re-clones the root disk, the volume stays, a memory snapshot of the old spec is dropped; `POST /restart` applies it now |
| [0025](0025-scheduling-labels-quotas-logs.md) | Placement within a create's region, a tenant never across regions; `?label=` selectors on listings; quotas per tenant checked at create and at a start's reservation; logs followed as NDJSON |
| [0026](0026-pool-encryption.md) | The pool is encrypted at its creation (ZFS, AES-256-GCM), one key per host made and kept by the fleet and loaded by the daemon at start (or a file on a single host); everything of a machine on the pool; no swap |
| [0027](0027-host-upgrade-and-version-skew.md) | Every binary and the init say `0.1.0+<commit>`; the wire is additive; SIGUSR2 hands the machines over to the next daemon, a stop suspends them and the next start boots them again; `host upgrade` runs the bootstrap script with a release and waits for the new version; drain is not retire |
| [0028](0028-first-real-host.md) | A real host: the pool a mirror of two devices (the free space of the OS's disks), a server bought by hand added and bootstrapped as an ordered one (`host add`), the API and endpoints on the private network with the public interface closed to all but SSH, the ZFS cache capped, a private repository's release read with a token |
| [0029](0029-exec-sessions-tty.md) | Exec sessions over a WebSocket (`GET …/exec`, Kubernetes' channel bytes): stdin streamed, a terminal with resize, the exit last; the host's close ends any exec; a session is use; the fleet relays bytes |
| [0030](0030-disk-limits.md) | Disk limits per machine (MB/s, IOPS, a burst) by Firecracker's rate limiter on the root disk and the volume, a rate per vCPU from the host's config under the machine's own, live by PATCH; disk bytes and throttling on `/metrics`; `cpu.weight` by size |
| [0031](0031-snapshots-and-restore.md) | Snapshots in the record, named, with memory as an option; a restore swaps each disk for a promoted clone of its snapshot, the replaced disk retired while newer snapshots or forks need it, so the backup base stays in the disk's history |
| [0032](0032-fleet-registry-backup.md) | The fleet's registry written to the object store once a minute when it changed and before a pool key is served, encrypted with age to a recipient whose identity is kept off the fleet's host; `briqyard-fleet restore` |
| [0033](0033-untrusted-input-through-maintained-parsers.md) | What someone else writes is parsed by a maintained crate fuzzed upstream: the gateway's DNS by `hickory-proto`, the ingress's request head by `httparse` (strict `Host`); what stays ours fuzzed by hand (`fuzz/`) |
| [0034](0034-object-store-crate.md) | The object store is Apache Arrow's `object_store` (S3 and a directory, one code path) on the workspace's reqwest: multipart with four parts in flight, retries with backoff, a get that resumes; errors keep the object's URL and the S3 error code, never a credential |
| [0035](0035-raw-backups.md) | Backups are raw sends (`zfs send -w`): the bucket holds ciphertext; the record carries the pool key's id, a restore asks for that key (its own file, or the fleet: served once, for a restore the fleet forwarded; a forgotten host's key kept as retired), receives, loads it and inherits the pool's key; backups in clear still restore |
| [0036](0036-registry-mirror.md) | A pull-through mirror per registry (Zot per region), tried first and the registry after it; a tag resolved by the registry with a `HEAD`, content checked by digest, so a mirror can only fail, never substitute |
| [0037](0037-firecracker-1-17.md) | Firecracker 1.17: the writable drives take discards and the guest's disks are mounted with `discard`, so deleted blocks go back to the pool; a suspend's snapshot stays synced (a torn memory file must never resume), a memory snapshot's is synced after the resume (the pause 42 % shorter); #6100 covers the failed-snapshot resume |
| [0039](0039-extraction-in-root-openat2.md) | Image layers written through one descriptor of the root: every path resolved by the kernel inside it (`openat2`, `RESOLVE_IN_ROOT`), every write an `*at` call that never follows the last name; Linux only |
| [0040](0040-volume-growth.md) | A PATCH grows a volume: its disk at once (`zfs set volsize`, the quota and the pool checked as at a create, never smaller), its ext4 filesystem in the guest at the next boot (the init, online), `pending` until then and that start cold; a fork, a restore or a restore in place never leaves a disk smaller than its record |
| [0041](0041-host-credentials-env-file.md) | The daemon's unit reads `/etc/briqyard/briqyardd.env` (root's, `0600`, optional) for its credentials, as the fleet's reads `fleet.env`; the operator writes it, briqyard never does; a change is read after a hand-over (ADR 0027), never a `systemctl restart` |
| [0042](0042-no-autoscaler-in-the-fleet.md) | No autoscaler in the fleet: placement counts each refusal by what ran out (memory or disk: a new host fixes it; pressure: the tenant's own host must be freed) and region, and shows each region's free room and largest slot on the fleet's `/metrics`, in `/v1/status` and `host ls`, for an external scaler that adds hosts with `host add`; the provisioners, `host order` and the release at the provider removed, `provisioner.bootstrap` now `bootstrap:` (the old place read for one release, with a warning) |
| [0043](0043-fleet-registry-writes.md) | The fleet's registry written one write at a time, each with the registry as it is when its turn comes (an async turn, the bytes compared with the last write's, synced before and after the rename); a write that fails after a host acted is logged and the host's answer stands; a machine call matched by its path, not its query |
| [0044](0044-placement-holds.md) | A placed create holds its memory and disk until a report received after its answer counts it; a refusal or no answer gives the hold back at once; a destroy's answer waits for the host's own figures; the capacity signals read the same |
| [0045](0045-backups-after-a-move.md) | Through the fleet, a destroyed machine's backups are reached on the host that holds them (every host asked at once for that machine's, `?machine=`), and a tenant's backups listed from every host; a host's listing reads the store 16 requests at a time and skips a record deleted meanwhile; a host's own pool key needs no forwarded restore, from its source or by id |
| [0046](0046-zvol-devices-checked-by-name.md) | A zvol's device is used only once `zvol_id` names it the disk, and a change event is sent for a device whose link is wrong (udev drops events, ZFS renames and removes devices after `zfs` returned); a rename waits for its device and link; `storage_stalled` while a `zfs` command runs past a minute; a backup racing a destroy answers 404/409, an exec on an exiting guest 409 |
| [0047](0047-repeats-folded-probe-timing-bookmarks.md) | Repeats of a use, a refusal or a readiness flip within 10 minutes of its line fold into one later line (`count`, `first_at`); a folded flip still takes a seq, its version; probes on a fixed period, the first run spread over a period just after a daemon start; a quiet watch sends `{"bookmark": seq}`; the probe timeout stays 5 s, Kubernetes's is 1 s |
| [0049](0049-tests-end-what-they-start.md) | A test ends what it starts, on any exit: a test binary exits once its parent is gone or after 6 minutes (`briqyard-testing`, installed by `#[ctor]`), the fake tools' waits end with their parent, the stand-ins' waits give up after 10 s; each shell suite cleans up in one trap on EXIT, INT, TERM and HUP (its own children by pid, what it changed put back, what it made destroyed) |
| [0050](0050-no-unplanned-restarts.md) | needrestart never restarts `briqyardd` or `briqyard-fleet` (`override_rc` in `/etc/needrestart/conf.d/briqyard.conf`, written by the bootstrap), since Ubuntu's apt hook restarts services without asking; unattended upgrades never reboot a host (`Automatic-Reboot` left false); `doctor` warns on either |
